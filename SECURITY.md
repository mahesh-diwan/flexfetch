# Security Policy

## Supported versions

| Version | Supported          |
| ------- | ------------------ |
| latest tag | ✅ |
| older tags | ❌ (upgrade) |

Security fixes land on `main` and ship in the next tagged release. There are no
separate LTS branches.

## Reporting a vulnerability

**Do not open a public issue for security vulnerabilities.**

Instead, report privately so the fix can ship before the details are public:

- **Preferred:** a private security advisory via GitHub
  (repo → *Security* → *Report a vulnerability*), or
- **Email:** open an issue asking for a private contact, or reach the
  maintainer through the GitHub profile.

You'll get an acknowledgment within 48 hours and a status update as the fix is
prepared. If the issue is confirmed, a fix + release is coordinated before the
advisory is published.

## Verifying releases

Every release artifact is **cryptographically verifiable** at three levels:
SHA-256 checksums (install.sh already checks these), cosign signatures, and
SLSA provenance.

### 1. SHA-256 checksums

`install.sh` verifies the tarball against its `.sha256` and refuses to install
on mismatch. To verify manually:

```sh
sha256sum -c flexfetch-linux-amd64.tar.gz.sha256
```

### 2. Cosign signatures

Each artifact ships with a `.sig` (detached signature) and `.pem`
(transparency-log certificate). Verify with cosign (install via
`brew install cosign` / `pacman -S cosign` / the cosign-installer action):

```sh
cosign verify-blob \
  --certificate flexfetch-linux-amd64.tar.gz.pem \
  --signature flexfetch-linux-amd64.tar.gz.sig \
  --certificate-identity-regexp '^https://github.com/mahesh-diwan/flexfetch/.github/workflows/release.yml@refs/tags/v.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  flexfetch-linux-amd64.tar.gz
```

The certificate identity pins the signature to this repo's release workflow at
a `v*` tag, so a stolen key alone can't forge an artifact.

### 3. SLSA provenance

Each release also carries `*.intoto.jsonl` (SLSA v1.0 provenance) generated by
the SLSA GitHub generator. Verify the build was produced by the trusted
workflow:

```sh
# After installing slsa-verifier
slsa-verifier verify-artifact \
  --provenance-path flexfetch-linux-amd64.tar.gz.intoto.jsonl \
  --source-uri github.com/mahesh-diwan/flexfetch \
  --source-tag <TAG> \
  flexfetch-linux-amd64.tar.gz
```

## Reproducible builds

Binaries should reproduce byte-for-byte from the tagged source. To verify that
a release binary came from the claimed source:

```sh
./scripts/verify-repro.sh v0.18.0          # builds the tag, diffs the hash
REPO=mahesh-diwan/flexfetch ./scripts/verify-repro.sh v0.18.0   # explicit repo
```

If the hashes differ, report it as a security issue — reproducible builds are
the final guarantee that what you run is what we shipped.

## Dependency advisories

`cargo-audit` runs daily in CI and files issues for RUSTSEC advisories; see the
audit workflow. The current dependency set is intentionally small and
mostly pure-Rust (see `Cargo.toml` feature gates) to minimize the attack
surface.
